On 2026-10-14 the user challenged trace-by-trace fixing ("are you reviewing architecturally against my hardware?"). Answer: local fixes give 5-15% each; ~12x is needed for 30 fps. Design doc written: Ps5\docs\agc-cpu-architecture-design.md (Design A per-epoch change sets, Design B pipelined translation). Next step agreed in principle: implement Design A step 1 after the user reviews the doc.

Hardware: i5-13600K (6P+8E), 64 GB RAM, RTX 2080 Ti on PCIe 3.0 (no ReBAR). Frame (H6Y/H6Z, in world): ~25 presents/10 s, GPU ~150 ms/present, GPU idle ~220-260 ms waiting on the draw worker (queue 0x0, 85-87% of one core by cycle count, ~69 us/draw, ~5,500 draws + 700 dispatches/s). Worker split: capture/specialization 19%, import/allocation bookkeeping 18%, guest data copies 17%, decode 8%, waits 5%, tracking/revalidation 7%, Vulkan recording only 4.4%.

Defects: D1 one translator thread per queue; D2 memory state re-proven per draw instead of per collect epoch; D3 unified-memory semantics on split memory (PCIe reads by GPU; page-protection ping-pong: ~15k VirtualProtect re-arms + ~12k debugger faults per 10 s); D4 no frame-to-frame reuse (draw recipe 0 hits).

Mistakes not to repeat: "worker 72% idle" was the second VulkanDevice's worker (two devices exist; the old sampler watched the wrong one). Kernel time is partly a sampler artifact (suspend APCs land on clock ticks) but 2-3 s/10 s is real; measure kernel with APS5_SAMPLE_WORKER_CPU_ONLY=1. The sampler must never take locks or allocate while a thread is suspended (that froze H6T; fixed by copying the stack, unwinding after resume).

Current best: branch palworld/play2-h5 in AnyPS5-play2 (local, unpushed), launchers run-dev\ab-h6y.cmd (sampled) / ab-h6z.cmd (CPU-only). Functional commits since H5: VRAM draw-input mirrors with batch prologue (APS5_LOCAL_DRAW_MIRROR=1, exact per-page validation), HostImportFor negative cache (c04aa0aee), mirror range collects once per epoch (cf81ae799), collect memo as merged intervals (251240fd1). GPU 363 -> ~150 ms/present; presents 21-22 -> 24-28/10 s. H6W-H6Z install their own libc.prx (backup: run-dev\libs\libc.prx.before-arena-counters).

Design A step 1 built as H7 (d825faba1 clean set across epochs via libc forget log, 2aac17f2f libc collectable() skips clean ranges; launchers ab-h7.cmd / ab-h7-off.cmd = same binaries with APS5_NO_CLEAN_SET=1). Pull-style "collect interest set per epoch" was rejected: ~250 epochs/frame makes it costlier than lazy walks. Step 1 ceiling is ~9% of the worker; the larger D2 slices are leases/regions (step 3) and snapshot copies. Counters: [guestmem] "clean-set hits/added/refused/forgotten/overruns", [local-arena-thread] collects.

H7 result: libc collect time 7.2% -> 2.5% of the worker, kernel 2-3 s -> 0.5 s, but presents/draw cost unchanged. H7S stacks: the freed time went into GPU waits at mid-frame CPU reads of GPU-written data (FlushForAccess -> SyncThrough). Same count of indirect-args syncs (78/10 s, DRAW_INDIRECT args written by compute, read on CPU by Pm4::ReadDrawArguments) but avg wait 3.4 -> 6.2 ms; pending-write sync waits 0.3-0.8 -> 0.9-1.2 s/10 s. Dispatch indirect is already GPU-side ([indirect] gpu-side 703, cpu-side 0); draw indirect is not. Conclusion: the frame is serialized at ~9 readback points per frame, which caps any CPU speedup (also Design B). The indirect-args waits are all rect-list DRAW_INDIRECT (op 0x24); moving them GPU-side was already H3 (green artifacts, masked coherence bug; no FPS, the wait moved to the next CPU read) — re-implemented by mistake and reverted on 2026-10-14 night. Removing one sync at a time does not pay; the open questions are the full per-frame list of CPU reads of GPU-pending data, and the green coherence bug the rect-list wait masks. Sync counts vary with scene even on the same binary (H6Y 100 vs H6Z 150 per 10 s); compare per-sync wait, not totals.

H7W (per-frame wait list, d9659f737, run-dev\ab-h7w.cmd, fixed screen from now on — user won't move; only day/night varies): GPU waits are only ~4 per frame, ~19 ms of a ~354 ms frame (5%), almost all rect-list indirect args (~3/frame, ~6.4 ms each); no locked GPU waits.
